# Landing-page blocks

TanSail blocks are ordinary React components backed by Zod-validated configuration. They are
composable without a page-builder runtime, global block store, or proprietary content format.

## Included families

| Family       | Variants                    | Typical role                                            |
| ------------ | --------------------------- | ------------------------------------------------------- |
| Hero         | Editorial, product, minimal | Establish the promise and primary action                |
| Logo cloud   | Responsive grid             | Show ecosystem or customer recognition                  |
| Features     | Grid, bento, split          | Explain capabilities with different levels of hierarchy |
| Use cases    | Outcome rows                | Connect an audience to a concrete result                |
| Testimonials | Quote grid                  | Add specific social proof                               |
| Pricing      | Two or three plans          | Make plan differences easy to scan                      |
| FAQ          | Native disclosures          | Resolve common objections accessibly                    |
| Stats        | Metric grid                 | Summarize measurable proof                              |
| CTA          | Banner, split               | Close with a focused next step                          |

## Compose a page

Import the configurations or define a new validated list, then render the components in the order
the story needs:

```tsx
import { LandingBlock } from "#/components/blocks/landing-block";
import { defineLandingBlocks } from "#/config/blocks";

const pageBlocks = defineLandingBlocks([
  {
    kind: "hero",
    id: "launch-hero",
    variant: "product",
    eyebrow: "New release",
    title: "A clear product promise.",
    description: "Explain the outcome in one short paragraph.",
    primaryAction: { label: "Start now", href: "#launch-cta" },
  },
]);

export function LandingPage() {
  return pageBlocks.map((block) => <LandingBlock key={block.id} block={block} />);
}
```

Use the exported block types when a reusable component needs a prop boundary. Keep the schema as
the source of truth instead of maintaining parallel interfaces.

## Styling contract

Blocks consume the semantic variables generated by `src/config/presets.ts`. Do not branch on
`harbor`, `horizon`, or `nightwatch` inside a block. Add a semantic token when a new visual role
cannot be expressed with the existing background, foreground, card, primary, secondary, accent,
border, typography, spacing, and geometry variables.

Block layouts use CSS container queries. This lets the local Gallery preview a mobile, tablet, or
desktop composition without an iframe and lets the same block respond correctly inside narrower
page layouts.

## Local Gallery

Run `pnpm dev`, then open `/gallery`. The route carries `noindex,nofollow`, stays out of the sitemap,
and can be removed before shipping when a project does not want to expose its design laboratory. It
provides:

- category filters;
- desktop, tablet, and mobile preview widths;
- Harbor, Horizon, and Nightwatch selection;
- light, dark, and system themes;
- stable block IDs for browser and visual regression tests.

## Motion

Wrap optional entrance motion with `MotionReveal`. Content remains visible during server rendering
and without JavaScript; it only enters a pending state after hydration. Reduced-motion users see
the final state immediately.
