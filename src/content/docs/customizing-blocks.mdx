# Customizing landing blocks

Every landing block has a Zod-backed configuration and a React component. The schema is the source
of truth for both hand-written pages and generated sites.

## Prefer an existing variant

Start by checking the local Gallery. A grid, bento, or split feature block often covers the desired
hierarchy without introducing another component.

## Add content through configuration

Keep titles, descriptions, metrics, actions, and lists outside the component. This makes the same
block reusable in page recipes and safe for generation workflows.

## Extend semantic tokens carefully

Blocks must not check the active preset name. If a new visual role is genuinely necessary, extend
the preset schema, provide a value for every preset, and consume the new semantic variable from
CSS.

## Preserve the accessibility contract

Use real headings, sections, lists, links, and disclosure elements. Keep reduced-motion behavior,
keyboard focus, and meaningful labels when changing the visual composition.
