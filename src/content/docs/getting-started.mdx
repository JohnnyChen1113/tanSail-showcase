# Getting started

TanSail runs without an account, database, secret, or external service. This guide establishes a working baseline, then helps you choose between manual configuration, a natural-language site brief, and a clean-room reference workflow.

<h2 id="install-and-run">Install and run</h2>

```bash
pnpm install
pnpm dev
```

The development server is normally available at `http://localhost:3000`. Visit `/en/` and `/zh/` for the localized homepages, `/docs/en/` for documentation, `/recipes/` for complete narratives, and `/gallery/` for isolated blocks. No `.env` file is required for the first run. The repository shorthand for the same server is `vpr dev`.

These paths do not create separate stacks. They only change how configuration is formed; all results use the same blocks, routes, tokens, and release gates.

<h2 id="first-change">Make the first change</h2>

1. Change the identity, production origin, navigation, actions, and footer in `src/config/site.ts`.
2. Update both English and Chinese homepage copy in `src/i18n.ts`.
3. Choose `defaultPreset` in `src/config/presets.ts`, or keep visitor selection enabled.
4. Refresh both locale routes and inspect the header, actions, and footer.

The site schema rejects titles outside 40–60 characters, descriptions outside 140–160 characters, origins with a trailing slash, malformed anchors, and unsupported internal routes. Correct the source configuration instead of bypassing validation.

<h2 id="verify">Verify the result</h2>

```bash
vp check
vp test run
vp build
```

The first command covers formatting, lint, and TypeScript. Unit tests cover schemas and invariants. The build produces the Cloudflare Worker and prerenders public pages. A successful dev server is useful feedback, but it is not a release gate.
