# Agent 工作流

TanSail 把仓库约束封装为两个 Codex Skill。它们不会用一句 prompt 直接改任意组件，而是先把意图变成可验证 brief，再通过维护中的 preset、recipe 和 block 实现。

参考工作流完成观察和转换后，仍会回到正常建站流程。不要同时让两个 Skill 各自生成一套页面。

<h2 id="brief-schema">Brief schema</h2>

Site brief 固定为 version 1，包含：brand name/tagline/description；primary audience、problem、outcome；页面 path、goal 和 sections；1–3 个 tone；一个有效 preset；一个有效 recipe；Cloudflare Workers deployment 与可选 domain。

```json
{
  "version": 1,
  "brand": {
    "name": "Northwind",
    "tagline": "Make complex releases understandable",
    "description": "A bilingual release communication product"
  },
  "audience": {
    "primary": "Product and engineering teams",
    "problem": "Release information is fragmented",
    "outcome": "Publish one clear release narrative"
  },
  "pages": [
    {
      "name": "Home",
      "path": "/",
      "goal": "Explain the product",
      "sections": ["hero", "features", "faq", "cta"]
    }
  ],
  "tone": ["technical", "editorial"],
  "preset": "horizon",
  "recipe": "saas-product",
  "deployment": { "target": "cloudflare-workers" }
}
```

<h2 id="dry-run">Dry run 与 apply</h2>

```bash
vp run generate:site -- --brief examples/generation/saas-brief.json
vp run generate:site -- --brief examples/generation/saas-brief.json --apply
vp run generate:site -- --brief examples/generation/saas-brief.json --check
```

第一条只打印 normalized JSON，不修改仓库；第二条显式写入；第三条验证 committed output 是否与 source brief 一致。Apply 后访问 `/generated-preview`，检查选中的 recipe、品牌、受众和 unresolved requirements。

<h2 id="write-boundaries">写入边界</h2>

生成器只能写入 `src/config/generated/*.json`，路径无法逃逸。未知 preset、recipe、tone、page path 或 section family 会失败。工作流不会自动安装包、添加登录、创建数据库或配置外部服务，也不能虚构客户、指标、认证、价格和法律声明。

Skill 可能在用户明确允许后调整 typed config 和内容，但仍必须保留无关 worktree 改动，并遵循 `AGENTS.md`、`.agents/` 和设计契约。

<h2 id="completion">完成标准</h2>

一个 Agent 生成结果只有在以下条件同时满足时才完成：所有 unresolved facts 被明确报告；中英文路由都能工作；设计与参考站保持原创差异；`vp check`、`vp test run` 和 `vp build` 通过；真实浏览器中桌面和移动导航、主题、链接、metadata 均已验证。
